# testParser (TLV_Parser)

Прототип парсера двоичных конфигурационных файлов платёжного терминала (TLV-формат, файлы `*.pst`). Эксперимент 2018 года: бинарные параметры терминала раскладываются на TLV-объекты и через рефлексию собираются в Java-POJO, сгенерированные из JSON-схем.

## Формат данных

Источник данных — файлы параметров терминала из каталога `tlv/` (тестовые примеры).

- Структура TLV (`TLVDataObj.java`): тег — 2 байта (big-endian), длина — 4 байта (big-endian), значение; заголовок — 6 байт.
- Старший бит (15) тега — признак вложенного (constructed) тега: такие теги разбираются рекурсивно.
- Первый байт значения примитива — маркер типа: hex, строка, byte, word, dword или double. Строки — в кодировке windows-1251.
- `tlv/DIRPARAM.mnf` — текстовый манифест пакета параметров: для каждого `.pst`-файла указаны контрольная сумма (16 байт), размер блока и путь.

## Что уже распарсено

`ParamsParser` по таблицам «tag → имя поля» и аннотациям Gson `@SerializedName` рекурсивно строит объекты. Тест `LibraryTest` разбирает все 12 справочников:

- валюты и BIN-диапазоны (`Currency.pst`);
- платёжные системы (`Paysys.pst`): EMV CA-ключи, сертификаты отзыва, DDOL/TDOL;
- карточные продукты (`Card.pst`);
- шаблоны ключей (`Keys.pst`);
- типы счетов с предпочитаемыми языками (`Account.pst`);
- шаблоны чеков (`Template.pst`);
- профили терминала (`Profile.pst`): EMV-параметры (TAC, CVM, лимиты, бесконтактные настройки);
- группы пользователей (`UsersGroups.pst`);
- организации — торговые точки (`Possessor.pst`);
- эквайринговые сети (`Acquiring.pst`);
- соединения с хостом (`Connections.pst`);
- терминал: идентификаторы, события, логирование, питание (`Terminal.pst`).

Не парсируются: `Common.pst`, `Newpar.pst` (строка «Parameters are updated») и сам манифест.

## Технологии

- Java, Gradle 4.3 (wrapper), плагин `java-library`.
- Генерация моделей из JSON-схем — `jsonschema2pojo` (аннотации Gson); сгенерированные классы закоммичены в `src/`, путь к схемам в `build.gradle` задан абсолютным путём на машине автора.
- Зависимости: Gson 2.8.5, Guava 23.0, commons-math3 3.6.1, JUnit 4.12. Проект Eclipse/Buildship (`.project`, имя `TLV_Parser`); исходники содержат комментарии в кодировке CP1251.

## Структура

- `src/main/java/` — `TLVParser` (разбор потока байт на TLV-объекты), `TLVDataObj` (тег/длина/значение), `ParamsParser` (TLV → POJO через рефлексию), `TLVParseException`;
- `src/main/java/com/inpas/parser/model/` — 53 сгенерированных класса моделей и перечислений;
- `src/main/java/com/inpas/type/HexString.java` — обёртка байтового массива с hex-представлением;
- `src/test/java/LibraryTest.java` — тест, читающий 12 `.pst`-файлов по абсолютным путям (не переносим);
- `schema/` — 24 JSON-схемы справочников и перечислений (`Def*.json`), связаны через `$ref`;
- `tlv/` — 14 тестовых `.pst`-файлов и манифест `DIRPARAM.mnf`.

## Статус

Прототип 2018 года: 11 коммитов с 29.06.2018 по 09.07.2018, после чего разработка остановлена. Данные в `tlv/` — тестовые (фиктивные идентификаторы терминалов и мерчантов, тестовые хосты). Тест и генерация моделей завязаны на абсолютные пути машины автора, так что проект в текущем виде не переносим на другую машину.
